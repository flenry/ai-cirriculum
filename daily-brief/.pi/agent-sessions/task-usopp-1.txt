## Problem
`pnpm brief` crashes on a fresh install with:
```
LibsqlError: SQLITE_ERROR: no such table: briefs
```
Root cause: `pruneOldBriefs()` runs before the DB schema exists. The `briefs` table is never created automatically — it requires a manual `drizzle-kit push` step that was never documented or wired into the startup flow.

## Your Job (Option A — Proper Fix)
Auto-create the schema inside `createDb()` so the `briefs` table always exists before any DB operation runs. No manual migration step required.

## Files to Read First
- src/db/client.ts
- src/db/schema.ts
- src/db/store.ts
- src/db/prune.ts
- src/index.ts
- drizzle.config.ts
- package.json
- CLAUDE.md

## Exact Fix Required

### src/db/client.ts
After creating the drizzle client, run an idempotent `CREATE TABLE IF NOT EXISTS briefs (...)` that matches the schema defined in `src/db/schema.ts`.

Use the raw libsql client to execute the DDL before returning the drizzle instance. Something like:

```ts
await client.execute(`
  CREATE TABLE IF NOT EXISTS briefs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    generated_at TEXT NOT NULL,
    weather_json TEXT,
    hn_json TEXT,
    github_json TEXT,
    wikipedia_json TEXT,
    status_json TEXT NOT NULL
  )
`);
```

Make sure to:
- Read schema.ts first to confirm exact column names and types
- Make `createDb` async (returns `Promise<DrizzleDb>`) since libsql execute is async
- Update all callers of `createDb` in src/index.ts to await it
- Update any test files that call `createDb` directly
