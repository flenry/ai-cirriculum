## Research Summary

### APIs — All Verified Live

| API | Endpoint | Auth | Rate Limit |
|-----|----------|------|-----------|
| **OpenWeatherMap** | `data/2.5/weather?q={city}&units=metric&appid={key}` | API key (query param) | 1,000/day free — safe for daily brief |
| **HN Algolia** | `/v1/search?tags=front_page&hitsPerPage=10` | None | No documented limits |
| **GitHub Notifications** | `/notifications?all=false&per_page=20` | Bearer PAT (needs `notifications` scope) | 5,000/hr authenticated |
| **Wikipedia Random** | `/api/rest_v1/page/random/summary` | None (User-Agent header required) | Not documented |

### Key Technical Decisions

- **SQLite schema:** Single `briefs` table, JSON blobs per section (`weather`, `hn_stories`, `github`, `wiki`, `html_output`), prune `WHERE date < date('now', '-30 days')` on each insert
- **Cron:** `node-cron` v4 (built-in TS types, zero deps), `CRON_SCHEDULE` env var (default `"0 7 * * *"`), with a `--run-now` flag for one-shot execution
- **Chalk:** Use chalk 5 (ESM) + `tsx` runner — cleaner than chalk 4 + ts-node for modern TS
- **HTML:** TypeScript tagged template literals — no external lib needed, snapshot-testable
- **Mocking:** `vi.mock()` per API module (e.g. `src/api/weather.ts`) — zero real network hits, no MSW overhead needed

### 8 Open Questions for board-prd
1. CLI one-shot vs daemon mode (recommend: `--run-now` flag)
2. Weather by city name vs coords (recommend: support both, city primary)
3. Graceful degradation when API keys missing (recommend: skip section, warn)
4. HN story count (recommend: 10, env-configurable)
5. HTML output path (recommend: `./output/brief-YYYY-MM-DD.html`)
6. Wikipedia redirect mocking approach
7. Brief deduplication on same day (recommend: upsert via unique `date` column)
8. Pruning timing (recommend: same transaction as insert)
