Build stage for the daily-brief project.

Project: daily-brief
Description: A personal daily brief generator that pulls weather, top HN stories, GitHub notifications, and a random Wikipedia article. Renders as terminal output (chalk) and HTML file. Runs on a cron schedule. Stores last 30 days of briefs in SQLite.

## Key Decisions (from handover/prd.md)

### APIs
- **Weather**: Open-Meteo `GET https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current_weather=true&hourly=relativehumidity_2m,apparent_temperature&forecast_days=1` — free, no API key
- **HN**: Algolia `GET https://hn.algolia.com/api/v1/search?tags=front_page` — no auth, top 10 stories
- **GitHub**: `GET https://api.github.com/notifications` — PAT via GITHUB_TOKEN env var
- **Wikipedia**: `GET https://en.wikipedia.org/api/rest_v1/page/random/summary` — no auth

### Database
- SQLite + Drizzle ORM
- `briefs` table: id, generated_at, weather_json, hn_json, github_json, wikipedia_json, status_json
- Pruning: delete records older than 30 days before each insert
- Duplicate handling: log warning + skip insert (no upsert)

### Rendering
- Terminal: chalk, dark colour scheme, structured sections
- HTML: ES6 template literals, inline CSS, dark mode (#0d1117 background)

### Scheduling
- Primary: single-run CLI `pnpm brief`
- Opt-in: `--watch` flag uses node-cron, reads CRON_SCHEDULE env var

### Partial Failure Policy
- Best-effort: always generate and store brief even if some APIs fail
- Per-section `status: { ok: boolean, error?: string }` on DailyBrief type

### Env Vars (.env)
- WEATHER_LAT, WEATHER_LON
- GITHUB_TOKEN
- CRON_SCHEDULE (default: "0 7 * * *")
- HTML_OUTPUT_PATH (default: "./brief.html")

### File Structure
- `src/api/` — weather.ts, hn.ts, github.ts, wikipedia.ts
- `src/db/` — schema.ts, client.ts, store.ts
- `src/services/` — brief-generator.ts
- `src/lib/` — weather-codes.ts, github-urls.ts
- `src/types/` — brief.ts
- `src/renderers/` — terminal.ts, html.ts
- `src/index.ts` — CLI entrypoint (single-run + --watch)

### Open Questions (watch for these)
- Open-Meteo hourly fields: take `hourly[0]` as current-hour value
- storeBrief duplicates: log warning + skip insert (NOT upsert)
- Wikipedia extract truncation: truncate at word boundary within 280 chars; skip truncation if extract < 280 chars
- README must warn that --watch misses runs if process dies

### Test Strategy
- Vitest + MSW for zero real network calls
- ≥ 90% statement coverage
- Test each API fetcher, DB layer, renderers, lib utilities independently
- Integration test: full brief generation pipeline
